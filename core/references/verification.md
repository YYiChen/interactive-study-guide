# Verification

验收分四层：Coverage、Dependency、Correctness、Technical。

## 0. 本轮验证范围与停止条件

两条路径见 `execution-profiles.md`。A–E 是质量维度，不是每轮全量复演的命令清单。

| 本轮改动 | 最小有效证据 | 何时扩大 |
|---|---|---|
| 裁图/图片替换 | 原页与候选对照、完整性；受影响的显示与引用 | 多处复用或样式/尺寸影响布局时查所有引用位置 |
| 结构图/公式/题解 | 原始依据或结构记录、相关方程/数值/单位核对 | 公共符号、跨节依赖或题目配置变化 |
| 教学交互 | 与公式独立对照的代表及边界状态、静态兜底 | 修改共享组件或发现状态联动错误 |
| 导航/布局引擎 | 受影响路由、展开/返回与相关视口 | 共享引擎变化再覆盖相关页面 |
| 措辞/局部排版 | 直接核对及受影响显示 | 改变概念、含义、条件时转内容核验 |

autonomous 可用等效方法，例如节点方程 + 连通性检查替代逐条机械填表；guided 使用预设步骤和可运行工具。**证据必须支撑本次改动**，两者都不能以自信语气或 PASS 数量代替核验。

相同文件/依赖未变、不存在新失败或未解决疑点时，不重复相同检查；只在修复相关错误、出现新修改或发现遗漏风险后重跑受影响项。连续失败先诊断并改变策略，不原样循环命令。工具被阻断时说明确切缺项，继续可完成部分，不反复探测、不绕过限制。

满足本轮适用检查且无未解决疑点即收口。仍有缺口则明确部分完成与影响，不伪称全部验收；不必为记录已知限制再制造一轮无收益测试。

## A. Coverage

- 当前材料的关键概念/公式/任务是否都有归宿；
- 本轮 delta 是否都处理；
- 旧页面知识是否有去向；
- 是否把 unknown 错写成 not-tested；
- 已确认能力是否有正式教学与有效练习。
- **视觉需求是否都被处理**：每条 `required` 需求要么有 `fig_id`，要么有明确缺口记录（原因 + 影响）；
- **图资产是否登记完整**：承载知识的图都有 `fig_id` + `locator`，没有只剩 `[IMG]` 的段落；
- **图更新是否造成丢失**：替换/重绘/移动图之后，知识、标注、参数、题目条件是否原样保留。

## B. Dependency

### Symbol Audit
正文每个新符号首次使用前是否定义。

### Figure-first Audit（视觉层）
- 首次依赖某张图的讲解，附近能否直接看到该图（不是"见第 3 节"、不是折叠在答案里）；
- 图上出现的符号、单位、方向、极性，正文是否解释过；
- 题目是否依赖一张不可见或藏在答案中的图；
- 原题复现是否保留证据图与条件；辅助图/改编题是否明确标注，题干、配置及答案一致；
- 读者能否从图过渡到方程或解题动作（图上标注 → 公式各项 → 第一步计算）。

### Prerequisite Audit
检查本轮改变的能力及其前置；大范围新建/重组时选跨节代表案例，不对局部修订强制随机抽三处。

### Solution-backward Audit
从答案逐步反查正文，任何未教学步骤都要修；答案里用到的每个图上标注，都要能在页面正文找到解释。

### Duplication Audit
同一知识是否存在多个完整版解释；若有，保留一个 Canonical Teaching Location。

## C. Correctness

关键公式/结论检查：
- 角色；
- 条件；
- 量纲；
- 边界/初值；
- 近似范围；
- 极限情况；
- 数值回代；
- 图文一致。

### Figure-consistency Audit（图、文、式、题、答五方）
1. 图中元件/节点/符号的命名与正文一致；
2. 图中参数值与题干给定值一致；
3. 图中方向/极性与公式里的正负号一致；
4. 图上声称的路径真实闭合；
5. 答案每一步都能在图上指出依据。

任一条不成立，改图或改文取实际正确者，并记入 Delta Log；不要只改一处让它"看起来对上"。

### Structure Audit（图本身对不对）
- 原始证据图：是否被裁掉端子、极性标记、图例、单位、条件注释；
- 结构教学图/重绘图：拓扑、连接点、方向、极性、参数是否与原图/题意一致；
- **题图**：原题证据是否保留；辅助重绘或教学改编是否区分来源、改变与核验；不得将不同配置混成同一题；
- 装置图与简化模型的对应关系是否成立（不是"两张都好看"就算对应）；
- 控制框图的求和符号、支路、反馈方向、信号名是否闭合且与方程一致；
- 波形图的横纵轴、单位、相位参考、假设是否写明。
- 工程类图纸按 `../../domains/engineering/domain.md` §8 的维度逐项核；无法判断的项记 `open-issue`，**不得标记为已验证**。

## D. Technical

运行：

```bash
node core/scripts/check_page.js page.html
```

输出语义：
- `PASS`：没有脚本能识别的错误或警告；
- `PASS WITH WARNINGS`：没有硬错误，但有需要人工复核的问题；
- `FAIL`：存在结构/语法/ID/导航等硬错误。

以下浏览器检查按 §0 选择受影响项；首次完整页面或共享引擎变化时再扩大覆盖。现成有效证据可复用；没有实际运行不能声称通过：
- 页签；
- sidebar；
- scroll-spy；
- gotoText；
- h2/h3 折叠；
- details；
- MathJax；
- 移动端抽屉；
- 动效数值一致性；
- **图像真的加载出来**（`naturalWidth > 0`，无裂图）；
- **裁切与缩放**：放大后标注可读，窄屏不裁掉关键结构，图内文字不与图注重叠。

### 三层证据边界（不可互相替代）

| 层 | 谁证明 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 机械层 | `core/scripts/check_page.js` | 结构、引用、ID、本地文件存在、声明完整性 | 图意正确、渲染正常、内容正确 |
| 渲染层 | 浏览器目视 / 自动化截图 | 图真的显示、不裁切、不重叠、交互可点 | 图像内容在学科上是否正确 |
| 内容层 | A/B/C 审计（含 §C Structural Audit） | 拓扑、极性、图文式题一致 | 渲染是否正常 |

任何一层通过，都不能推出另一层通过。

## E. 领域专项审计

领域适配器可追加自己的一层验收（放在 D 之后，不替代 A–D）：

- **工程**：量纲、边界/初值、近似范围、极限情形、数值回代（本文件 C 节的工程口径）。
- **语言学习（IELTS）**：每个知识节点 `sources[]` 非空；个人强调与经验总结是否保留；是否出现了资料里没有的内容（类型、技巧、素材、范文）；答案是否默认折叠；IA 是否经用户确认；未观察到的能力是否被误写成“不考”。

领域审计的检查项写在对应 `domains/<domain>/` 文件里，本文件只规定它必须存在。

## Checker 不能做什么

它不能可靠证明：
- 学科公式正确；
- 前置知识真的完整；
- 某个题型一定会考；
- 某段解释真的适合零基础；
- 图的结构/拓扑正确（它只比对声明与文件，不理解电路）；
- 图片真的渲染出来、裁切是否合适、是否与其他元素重叠（属于渲染层）；
- "这条视觉需求已被满足"——它只能证明声明了对应 `fig_id` 且文件存在。

这些必须通过 A/B/C 的人工或模型审计完成。
