# Content Rules

本文件只包含**跨领域通用**规则。具体学科公式与领域专属口径不得写成全局强制规范：领域差异写在 `domains/<domain>/`（工程见 `domains/engineering/domain.md`，IELTS 见 `domains/ielts/page-patterns.md`）。

## 1. 概念首现

第一次出现一个新概念，至少让读者知道：

- 它解决什么问题；
- 名称是什么意思；
- 与已有知识是什么关系；
- 后面会在哪里用。

不要用“显然”“容易知道”跳过零基础读者真正需要的连接步骤。

## 2. 符号首现

（语言学习类资料中的术语、表达、题型名同样适用本节：首次出现要说明含义、使用场景与相邻概念的区别，见 `domains/ielts/domain.md` §5。）

首次使用前解释：读法、含义、单位/量纲、上下标/点号/偏导/向量等记号、量的角色。

同一符号在不同章节或语境含义变化时必须重新声明。

## 3. 公式首现

至少回答：

- 它是什么角色：定义 / 基本定律 / 本构 / 推导 / 经验 / 近似；
- 每项是什么；
- 依赖哪些前置；
- 成立条件；
- 典型误用；
- 可行时做量纲或极限检查。

不要把“把一组量重新命名”写成“推导出了新定律”。

## 4. 推导

推导的目标不是展示代数长度，而是解释“为什么下一步成立”。

可省略熟练读者显然的机械运算，但不能省掉：
- 新方法第一次出现；
- 关键替换；
- 边界/初值进入的位置；
- 近似或舍项理由；
- 从数学结果回到物理/几何含义的解释。

## 5. 经验关系与近似

凡是经验系数、拟合关系、常见近似或简化模型，都应说明：

- 来自哪里；
- 适用范围；
- 为什么当前可用；
- 超出范围会发生什么。

不要让学生把近似当恒等式。

## 6. 图与图表

图不是插图，是论证的一部分：读者必须能从图上读到某个结构、方向或趋势，并据此完成一个动作。

配图的判据是**视觉需求**，不是数量：

- 读者要追踪连接、判断方向/极性/相位、辨认空间位置与装配关系、读波形坐标、跟随信号流与回路、对照两个状态的差异 → 该学习任务需要对应图像支持；
- 纯定义、纯代数通常不需要图；不要为凑数造图，也不要用一张无关图"关闭"一条需求；
- "每个知识板块至少 1 个视觉锚点"只是**下限提示**，不是充分性标准；组合需求（结构图 + 半周路径、电路 + 输入输出波形、装置图 + 简化模型）要按需给两张；
- 判据、需求字段与状态见 `visual-material.md` §2、§6。

每张图必须能说明自己是哪一种——**原始证据图**（保留考试口径，能拿到就用）、**结构教学图**（简化的或重绘的，结构须核验）、**状态演化演示**（交互）。重绘与补充不得伪装成原图，也不得用漂亮画面掩盖未核验的结构。

硬要求（不随页面原型放松）：

- **不是每张图都要可交互**。按图型分级：A 结构识别类（结构图、部件/关系示意、流程框图）默认静态；B 查表取值类（参数表、分级表、对应关系表、速查表）优先可交互查表；C 关系演化类（参数敏感性 / 时间演化 / 几何关系 / 图形读法 / 方法对比 / 量级感）按学习收益选交互或清楚的静态对照，不因图型名称自动增加控件；各领域的典型例子见对应领域适配器；
- 每张图带图注三要素：让什么变得可见 / 观察什么 / 结论是什么；
- 图必须与正文、公式、题目、答案一致——五条一致性检查见 `visual-material.md` §5。

坐标轴、单位、正方向、参考状态和关键标记必须可读；图号全页唯一；多套坐标系并存时注明各自基准。三类图型的判定口径见 `interactive-patterns.md` §1。

表格用于"对比和收束"，不要在预习页一上来用大表格代替因果推进；查表取值型表格按 B 类优先做成可交互（可调量 → 对应行/数值实时可见）。

## 7. 例子

最小示范优先选择：
- 数字简单；
- 能隔离当前新知识；
- 不引入额外背景负担；
- 能让学生检查答案是否合理。

后续再增加真实工程或综合场景。

## 8. 练习

题目前不固定放大段 prep。

使用 Dependency Audit：
- 已教过 → 直接练；
- 久未使用 → recall；
- 通用缺口 → 回正文；
- 局部技巧 → bridge。

**题图保护**：原题复现保留可获得的原图及条件，与题干同时可见。辅助图与教学改编按 `visual-material.md` §3.1 区分角色、来源和改变；解答必须对应当前使用的配置。

答案必须解释关键决策，不只给代数过程。

## 9. 自检

自检是可选教学组件，不要求“每页固定 4–6 题”。

适合在一个能力节点完成后，用 1–3 个高价值问题验证：
- 能否用自己的话解释；
- 能否区分易混概念；
- 能否判断何时使用；
- 能否做一个最小计算或判断。

如果自检只是重复正文句子，可以省略。

## 10. 易错点

局部易错点放在首次教学附近；跨章节反复出现的易错模式在总结中集中对照。

格式优先：`陷阱 → 为什么错 → 正确动作`。

## 11. 语言

解释要精确，但允许口语化比喻。比喻只能帮助建立直觉，不能替代正式定义。

如果比喻在边界情形会失真，应明确“比喻到这里为止”。

## 12. 真实反馈如何沉淀

用户指出某个具体学科问题时，先抽象成通用症状再写回规则。

例如：
- “某个字母突然出现” → 符号首现规则；
- “题目用到前面没教的方法” → Question Dependency + Solution-backward；
- “同一知识反复讲” → Canonical Teaching Location + recall；
- “一补资料页面就乱” → incremental impact analysis；
- “某个经验常数凭空出现” → 经验关系四件事。

不要把具体学科公式永久写进本文件。
