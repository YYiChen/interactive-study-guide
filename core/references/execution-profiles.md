# Execution Profiles · 引导执行与自主执行

本文件只调整执行支撑程度。工程、数学、语言等领域仍由真实材料决定；同一项目的不同工作单元也可使用不同路径。

## 1. 选择方式与共同底线

优先级：用户本轮指示 > 用户/项目显式固定的执行设置 > 同类任务的实际表现与工具条件 > 保守默认 guided。项目可选用 `project.execution.profile`，不要求迁移旧状态，也不要求在学生页面展示模式。`selected_by=conservative-default` 或 `observed` 是自动选择记录，不是用户固定设置；获得新任务证据或工具条件变化时可重新选择，不能因模板默认值把成熟执行者永久锁在 guided。

用户明确允许自主，且当前执行者在同类任务已有可检查的设计/修改/验证证据时，采用 autonomous。未知模型或陌生工具采用 guided，不因模型名称、价格或自报“很强”自动升档；也不要求为了选档单独调用模型做能力测验。用户显式选择 autonomous 时尊重选择，不额外设置考试或审批。

自主是过程自由，不豁免这些结果：

- 课程明确内容、必要补充和假设可区分，不能编造来源、考试结论或“已验证”。
- 修改不静默删除知识、个人强调或原始证据；稳定引用和现有可用导航得到保留。
- 图、正文、公式、题目配置与答案一致；材料冲突如实记录。
- 核验记录能对应实际操作；结构 PASS、真实渲染和学科正确性互不替代。
- 已有用户确认及其授权边界有效；模式本身不增加改范围、调用别的模型或外部发布的权限。

## 2. guided：把复杂任务拆成可执行动作

不让能力有限的执行者同时决定全课程结构、裁图范围、电路拓扑、交互实现和验收。按有依赖的顺序完成一个**完整学习单元**，不是每张卡都等待用户批准。独立且已确定的操作可批量执行。

| 操作 | 输入与输出 | 何时继续 |
|---|---|---|
| 定位材料与目标 | 来源页/段/题号；学生要完成的动作；现有位置 | 明确本单元讲什么、需要看到什么 |
| 准备视觉证据 | 原图或完整页；必要时用 `../scripts/prepare_figure.py` 生成候选与对照 | 能确认必需标注完整；不能确认则保留整页并记缺项 |
| 填入成熟结构 | 从 `../assets/study-page-template.html` 选合适原型；复用现有组件 | 图与讲解就近、符号有定义、题干条件完整 |
| 必要增强 | 优先用 `interactive-patterns.md` 已有骨架；先有静态正确表达 | 只有交互确有教学收益且结果可核验时才增加 |
| 本单元验证 | 对照原材料、计算和相关技术检查 | 没有未解决关键疑点时扩展下一单元 |

工作单只需：目标/范围 → 原始依据 → 表达选择 → 适用核验与未解决项。具体符号表、依赖图或视觉需求表按需扩展，不造九张空表。

不会可靠识图时不猜裁剪框；不会核验新结构时不凭文字重绘。保留原图、整页或准确的定位与缺口，比自创“看似完整”的输出更合适。仍须完成不依赖该缺口的已授权工作。

### 一个最小示范

“解释正、负半周”：先展示同一座原桥，标明输入端、负载端及符号；用两张核验过的状态图解释闭合路径；若读者需要连续调相位，再使用可靠的交互。不要一开始就从零画复杂动画。

对语言资料，同样可以先完成一个策略的原例、解释与可检验练习，再扩展；不强制为语法或代数定义添加电路式配图。

## 3. autonomous：允许自行设计，提供等效证据

可自主决定：板块数量和顺序、图文并排或分层、组件风格、辅助重绘、静态状态组、交互设计、工具链、批量操作与验证方法。维护已有稳定的页面契约，但不要求逐字复制模板、固定图数或固定交互形式。

不必逐表填全部施工图，也不必每次复演 guided 的步骤。保留简短的关键取舍、来源、实际验证和未解决项即可。

例子：

- 可以用清楚的节点图加电位表解释电压参考，无需为了“C 类”强行加滑块。
- 可以在原题旁增加易读的辅助重绘；保留原证据，核对节点、极性与条件，不为可逆表达反复问许可。
- 可以设计超出现有骨架的新交互；用与实现相对独立的公式/数值及边界状态核验，不要求用指定测试框架。
- 已用节点方程、导线连通性和原页对照证明相关改动，不再额外填写同义的“看起来正确”表格。

需要更多支撑时只对困难部分切回 guided，例如自主组织全文但对陌生图纸先复用原图。模式切换不是停工理由，也不降低最终质量。

## 4. 验证如何收口

按本轮改动选最小有效证据，矩阵见 `verification.md` §0。区别于“少测以省时间”：必须覆盖受影响的实际风险，只是不重复没有新信息的检查。

1. 写下受影响对象及适用检查，复用未失效的已有证据。
2. 实施并取得相关证据。小措辞修改不触发全课程、全视口、全控件遍历；共享引擎变化才扩大覆盖。
3. 有失败先定位原因，修复后只重测受影响项；相同失败不原样循环，也不通过删断言/改正确性标准制造 PASS。
4. 检查已通过，且没有新增修改、新失败或未解决疑点，即停止并交付。不能仅因还有更多工具可用而继续检测。
5. 实际工具/权限阻断时说明缺项，完成独立部分；不把“未运行”写成通过，也不无限等待或绕过限制。

检查器警告需判断是否适用于当前内容；确属不适用或已由等效证据覆盖时说明理由后收口，不为凑“零警告”改变正确内容。新建合法组件也不必强行改成旧检查器偏好的版式；补足必要检查或明确工具边界即可，不能忽略真实错误。

证据可以是来源页、原页/裁图对照、节点与参数映射、独立回代结果、运行日志、相关状态截图；文件名、勾选和模型自信不是证据。

## 5. 几种预期决策

| 请求/条件 | 预期行为 |
|---|---|
| 未知工具，要求从 PDF 补图 | guided；先整页与原图，生成候选对照，不能猜图意 |
| 用户允许成熟执行者自主重排讲解 | autonomous；自行选版式与组件，保留知识和稳定引用，只验证受影响路径 |
| 仅修正一处文字或裁图留白 | 两种模式都局部处理；不重新盘点全部课程、不重复跑所有交互 |
| 原题与想用的图参数不同 | 区分辅助图或改编题，核对新配置答案；不能强行改文字来配图 |
| 内容核验已有充分证据，但浏览器不可用 | 如实说明渲染未验收，交付可完成部分，不循环探测或声称整体通过 |

这些是行为例子，不是按字面匹配的分类器。模式与工具能降低遗漏和操作负担，不能保证缺乏必要视觉/专业能力的模型独立完成所有内容核验。
