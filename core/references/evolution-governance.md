# Evolution Governance

## 1. 新内容先归位，不先追加

收到补充后，先问：

- 它属于已有正式教学地址吗？
- 它揭示了一个此前缺失的先修吗？
- 它改变了考试优先级吗？
- 它证明原顺序有问题吗？

只有真正出现新读者问题时才新增板块。

## 2. 禁止补丁墙

避免：
- “补充说明 1/2/3”；
- 页面末尾不断追加杂项；
- 同一知识在多个位置各写一套完整版；
- 用折叠隐藏结构问题。

## 3. 合并原则

两个段落若承担同一教学任务：合并到 Canonical Teaching Location。

其他位置保留 recall/链接。

## 4. 重构原则

先做 Coverage Baseline，再动结构。

每个已有知识项都要有去向，不能因为“新版更简洁”而消失。

## 5. 冲突材料

遇到版本/口径冲突：
- 识别来源与时间；
- 判断是纠错、简化还是适用条件不同；
- 页面只保留一个清晰主口径；
- 必要时用 note 说明差异。

## 6. 用户反馈

“看不懂”优先检查：顺序、未定义符号、缺先修、公式角色、题目依赖；不要第一反应只是加更多文字。
