# Page Structure

## 1. 总体信息架构

推荐：

- 🏠 开始 / 总览
- 若干知识板块
- 📚 例题
- 📝 训练
- 🧾 总结

这是默认框架，不是硬性页数。小课程可合并，大课程可拆多 HTML。

复习层尽量只有一个一级入口“总结”。

## 2. 标题层级

正文使用：
- h1：页/板块标题
- h2：主要读者问题
- h3：该问题下的自然子问题

尽量三级封顶；不要 h2 直接跳 h4。

一个节很长且包含多个独立子问题时拆 h3；若 h3 过多，重新检查 h2 边界。

## 3. 左侧大纲

保留成熟 sidebar 引擎：
- 自动采集 h2/h3/题目；
- 折叠；
- scroll-spy；
- 跨页跳转自动展开祖先；
- 小屏抽屉。

目录的作用是“定位和恢复上下文”，不是展示所有微知识。

## 4. 顶层页签

页签表示不同学习任务，不要把每个知识点都变成一个 tab。

知识板块可根据课程规模增减。

## 5. 渐进披露组件

- `.concept`：核心概念
- `.formula`：公式/关系
- `.translation`：人话解释
- `.recall`：短提醒
- `details.bridge`：局部知识桥
- `details.deep`：非主线深挖
- `.practice`：练习
- `details.answer`：答案
- `.check`：可选自检

bridge/deep/answer 默认折叠。

## 6. 练习布局

练习前不强制 prep。

若需要提示：
- 简单提醒用 recall；
- 局部特殊技巧用 bridge；
- 通用知识缺失必须回正文。

## 7. 总结页

总结建议包含：
- 主线复述；
- 符号/单位；
- 易错对照；
- 速查/决策树。

但只放已经教学过的内容，不第一次引入新方法。

## 8. 首页

首页只承担：
- 这部分学什么；
- 需要什么基础；
- 最终要会什么；
- 建议学习路径；
- 当前资料状态（如确有必要）。

不要把首页做成第二本教材，也不强制同时放板块地图、练习总索引等所有导航组件。

## 9. gotoText

跨页跳转 key 必须尽量唯一。完成后用 checker 验证。

稳定知识节点若移动，应尽量保留兼容锚点。
