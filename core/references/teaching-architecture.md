# Teaching Architecture

这份文档规定“怎么把零散课程材料组织成可学会的课程”，不规定任何具体学科公式。

## 1. 先定义读者状态

默认是预习：读者第一次系统学习当前范围。

允许假设正常先修课的基础运算，但凡某个先修知识会阻断当前理解，就补最小必要内容。

复习、查漏、冲刺时可以压缩，但不要用复习式表格替代第一次教学。

## 2. 能力先于知识清单

先问学生最终要能做什么，再决定要讲哪些知识。

Mastery Map 的能力可以是：解释、识别、计算、建模、推导、证明、判断、作图、读图、选方法、检查结果。

不要把“出现过一个名词”自动升级成独立能力。

## 3. Prerequisite Graph 决定顺序

每个能力向前追依赖，直到 Baseline Contract。

如果 B 必须依赖 A，则 A 必须先正式教学；不能等做到题时才补。

同一概念若被多个后续能力依赖，应尽量提前到共同上游，而不是在多个题前重复。

## 4. Canonical Teaching Location

每个核心概念设一个正式教学地址，完整承担首次教学。

一个完整教学节点通常包括：

1. 为什么需要；
2. 名称与符号；
3. 关系/公式；
4. 来路；
5. 条件与边界；
6. 最小示范；
7. 能力检查。

并非每个微小名词都需要七段文字。粒度以“读者能否独立使用”为准。

## 5. 局部唤醒而不是重复教学

后续再次遇到：

- 已熟悉 → 直接用；
- 可能忘记 → `.recall`；
- 当前情境特有小技巧 → `.bridge`；
- 非主线深挖 → `.deep`。

如果某个 bridge 在后面反复出现，说明它不该是 bridge，应升格为正式教学。

## 6. 练习梯度

### Guided Practice
刚学完，允许提示目标或第一步，但不直接替学生完成核心决策。

### Transfer Practice
换数字、场景、表示方式或问法，要求学生自己识别方法。

### Exam Practice
尽量模拟真实考核，不泄露方法标签。

练习覆盖“能力单元”，不是“每个符号一题”。一个综合题可以覆盖多个已经成熟的微知识。

## 7. Solution-backward Audit

页面完成后，从题目答案反查：

- 每个符号在哪里第一次教；
- 每个公式在哪里正式出现；
- 每个变换/建模动作是否教过；
- 每个假设、边界条件、近似是否有来源和条件；
- 学生是否必须做一个此前没有练过的关键决策。

出现缺口时优先回修正式教学地址，而不是在答案旁补一段说明。

## 8. 预习层 / 应用层 / 复习层

### 预习层
单线推进，先问题后形式化。表格主要用于讲完后的收束。

### 应用层
例题与训练，把已学知识组合起来。

### 复习层
压缩成主线、符号表、易错对照和决策树。不得第一次引入新知识。

## 9. 板块边界

一个板块最好能回答一句明确问题。

需要拆分的信号：
- 一个板块同时回答多个互不依赖的问题；
- 一个 h2 很长却没有自然子问题；
- 相邻板块可任意交换，说明它们只是并列清单；
- 新材料总被追加到“补充/其他”。

## 10. 知识深度停止条件

继续补充，直到同时满足：

- 学生能理解当前材料；
- 能完成当前已观察的能力任务；
- 不再依赖未解释的新概念；
- 再继续展开只会进入非必要理论或远离当前课程。

到这里停止主线，剩余内容若有价值放 deep。
