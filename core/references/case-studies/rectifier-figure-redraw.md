# 案例：桥式整流图 —— 图看起来像电路，连接却是错的

> 来源：一门工科课程的"机电与测量"单元（2026 秋）。此处只保留抽象后的问题结构，具体课程的文件名、元件编号与页码不入通用规则。

## 事实

1. 原始材料里有整流桥的图（幻灯片与教材各一版），也有桥式整流的文字说明。
2. 生成的学习页**没有使用任何原始图片**：页面内 6 张图全部是手写内联 SVG。
3. 其中"全波整流动画"的 SVG 画法：交流源在左、四个二极管排成左右两列（D1/D2 在左，D3/D4 在右）、电机 M 单独在右，用直线把源连到左侧两只、把右侧两只连到 M。
4. 图注与正文写的是"正半周 D1→M→D3 导通，负半周 D2→M→D4"，这是桥式整流的正确结论。
5. 判定：**图的连通关系与文字结论不一致**——按图上的连接，源的两端只接到左侧两管，负载只接到右侧两管，不构成桥；而且四个"二极管"画成灰色方块，没有三角形+横杠符号，读者无法从图上判断极性，也就无法验证导通对。

## 为什么会发生

- 材料读取阶段只取文字：`MinerU` 已抽出的千余张图没有任何一张进入页面，也没有图资产登记（无 `fig_id`、无定位、无关联）。
- "每个知识板块至少一个视觉锚点"被当成验收标准：板块里有了一张图就算达标，图的**内容**没有被审。
- 交互优先：因为"整流是随时间变化的"，就先把动画做出来，连通关系是在写动画的过程中"顺手画的"。
- 没有任何一步要求"把图上的路径从电源走一遍回电源"。

## 抽象出的可迁移规则（已写入 core / engineering）

| 问题 | 规则落点 |
|---|---|
| 图在读取时丢失 | 文字与视觉并行读取；承载知识的图必须登记 `fig_id` + 定位（`../visual-material.md` §1） |
| 一张无关图被当作覆盖 | 配图充分性按视觉需求判定，不用板块配额（`../visual-material.md` §2） |
| 有原图却凭文字重绘 | 素材降级阶梯：L1 解析图 → L2 内嵌 → L3 原页渲染裁剪 → L4 重绘（须核验）（`../visual-material.md` §3） |
| 图形似而拓扑错 | 五条一致性检查，其中"路径真实闭合"与"图上方向/极性与公式符号一致"是硬项（`../visual-material.md` §5） |
| 器件符号不可辨 | 工程核验维度：符号、端子、极性、连接点、旁路（`domains/engineering/domain.md` §8.1） |
| 交互先于结构 | 正确性先于交互；交互必须检查代表性状态与边界状态（`../interactive-patterns.md` 前置约束） |
| 检查器全绿 | checker 只证明声明与文件对得上，不证明拓扑（`../verification.md` 三层证据边界） |

## 复现要点（供回归演练）

在隔离目录用最小材料复现：

1. 取一页含桥式整流图的原始幻灯片，只给模型文字（不给图）；
2. 要求生成"全波整流"板块；
3. 预期失败模式：手绘 SVG、二极管画成方块、源与负载接在同侧、图注正确但图不支持；
4. 施加 v5.2 规则后应出现的行为：先登记图资产、开一条 `required` 视觉需求、优先用原图或原页裁剪；若重绘，必须先声明"依原文重绘"并完成 §5 五条检查，否则记为 `open-issue`。
