# Visual Material · 图像的读取、选择与核验

本文件管一件事：**承载知识的图像如何从原始材料进入学习页，并如何被验收**。

它不要求"多配图"，也不把某门课的具体电路写成规则。它补的是三个机制性缺口：读材料时图丢失、图进了页面但结构错误、验收时只看"有没有图"。

读这份文件的时机：

- 材料含 PDF / PPT / 扫描页 / MinerU 解析结果 / 板书照片，且可能出现图；
- 页面需要判断"这里到底要不要图"；
- 已有图被替换、重绘、移动，或用户指出图文不符。

图型分级（A/B/C）与交互代码骨架仍归 `interactive-patterns.md`；本文只管**图像作为证据与结构载体**的部分。工程类图纸的具体核验维度见 `domains/engineering/domain.md`。

---

### 执行路径与裁图支撑

guided 按 `execution-profiles.md` §2 逐单元处理；autonomous 可以选用自己的素材与核验工具，不必复演相同操作。两者的证据、题目条件与正确性要求一致。

裁图先看完整来源页，列出本任务不能丢的端子/单位/条件，再提议区域；用 `../scripts/prepare_figure.py` 生成“原页上的框 + 候选图 + 来源 JSON”。默认无框就是整页。示例：

```bash
python core/scripts/prepare_figure.py lecture.pdf --page 7 --id FIG-07 --out review/fig07-full
python core/scripts/prepare_figure.py lecture.pdf --page 7 --box 0.10 0.20 0.90 0.85 --padding 16 --id FIG-07 --out review/fig07-candidate
```

坐标为完整页的归一化 xyxy；页码从 1 开始。示例框只是命令格式，不是推荐裁剪范围。也支持已渲染 PNG/JPEG；PDF 按环境使用 PDFium 或 PyMuPDF，无库时用已有渲染工具，不自动安装。

查看对照后再采用候选。不能确认完整性就扩大范围或保留整页；缺视觉能力时不编造框、不把脚本输出当作已看过。工具只保证坐标、文件和来源记录，不能判断图意。autonomous 的等效方法只需保留相同的可追溯结果，不强制使用本脚本。

## 1. 读取契约：文字与视觉并行

读材料时同时产出两份结果，缺任一份都算材料未读完：

| 产出 | 内容 | 落在哪 |
|---|---|---|
| 文字覆盖 | 概念、符号、公式、条件、推导、例题、易错点 | Coverage Baseline（`../assets/planning-workbench.md` §2） |
| 图资产 | 每张承载知识的图及其定位、可用路径、上下文、关联 | Figure Asset Ledger（`../assets/planning-workbench.md` §2c） |

### 1.1 先判断"这张图是否承载知识"

满足任一条即为承载知识（必须登记）：

- 正文出现"如图所示 / 见图 / 图 X"并依赖它解释或解题；
- 图包含正文未复述的结构、连接、方向、极性、坐标、波形、时序；
- 题目条件只以图给出（参数、标注、拓扑、边界）；
- 教师用图承担推导步骤（框图、流程图、状态图）。

以下**不进教学页**，但也不删除原件：封面、装饰、校徽、纯文字投屏、与当前范围无关的插图、纯粹烘托氛围的照片。

### 1.2 图资产最小字段

沿用 `../assets/planning-workbench.md` 的 Provenance Ledger 风格，不另建数据库：

| 字段 | 说明 |
|---|---|
| `fig_id` | 稳定 ID，如 `FIG-<单元>-<序号>`。一旦被页面或题目引用就不再改名 |
| `material_id` | 来源材料（对齐 Material Ledger） |
| `locator` | 页 / 幻灯片号 / 图号 / 时间码 / 解析文件内的位置 |
| `path` | 可用图像路径，或"需渲染（页码/区域）"这类明确待办 |
| `context` | 附近标题 + 图注 + 一句话说明它讲什么（用于判断是否被正确理解） |
| `role` | `evidence`（原始证据图）/ `teaching`（结构教学图）/ `demo`（状态演化演示） |
| `links` | 关联的 `knowledge_id` 或题目 id |
| `integrity` | `complete` / `cropped-questionable` / `unreadable` / `partial`（含判断理由） |
| `status` | 见 §6 状态阶梯 |

### 1.3 硬性禁令

- **禁止只留 `[IMG]` 或"此处有图"占位**并宣称材料已提取完成。占位必须带 `fig_id` 与 `locator`，否则视为未读取。
- 文本与图可以分开存储（md 正文 + images/ 目录），但**关联不能丢**：任何进入页面的图都必须能反查到 `material_id` + `locator`。
- 解析器抽出的图**不等于**已正确识别的教学图；`fig_id` 是人工/模型判定后的登记，不是解析产物的编号。
- 图里有 OCR 文字，**只说明文字可读**，不说明连接、方向、结构已被理解。
- 同一张图被重复抽出时，按"同一 `fig_id` + 多条 `locator`"合并；若不同版本在标注、参数或结构上有差异，**保留差异并登记**，不要静默取其一。

## 2. Visual Requirements：什么时候"必须有图"

### 2.1 定位

"每个知识板块至少 1 个视觉锚点"只是**下限提示**，不能作为视觉充分性的验收标准。真正的验收单位是**视觉需求**：某个学习任务是否必须看见某个结构才能完成。

判据——只要读者要完成下列任一动作，就应登记一条 `required` 需求：

- 追踪连接（哪条线接到哪、是否闭合）；
- 判断方向 / 极性 / 相位 / 先后；
- 辨认空间位置或装配关系；
- 读波形、坐标、区域边界；
- 跟随信号流、控制回路或能量路径；
- 对照两个状态的差异（正半周 / 负半周、开 / 关、线性 / 饱和）。

反之，纯定义、纯代数、纯术语辨析通常**不需要**图。不要为了满足配额造图。

### 2.2 需求表字段

| 字段 | 说明 |
|---|---|
| `vr_id` | `VR-<单元>-<序号>` |
| `subject` | 对应的 `knowledge_id` 或题目 id |
| `reader_action` | 读者要完成的动作（"判断哪两只二极管导通"这类） |
| `must_see` | 必须看见的结构或关系（"桥的四臂与负载跨接位置"） |
| `need` | `required` / `helpful` / `unnecessary` |
| `fig_ids` | 候选或已用的图（可多个） |
| `anchor` | 页面 + 锚点（`c2-rectifier` 这类） |
| `status` | 见 §6 |
| `note` | 为什么这样判、缺口原因 |

### 2.3 组合需求

一个任务可能需要**一組图**，不要用一张图硬凑：

- 结构图 + 半周路径图（同一张图上叠加会看不清）；
- 电路图 + 输入输出波形；
- 装置图 + 简化模型/受力图；
- 框图 + 对应传递函数。

登记为一条需求、多个 `fig_ids` 是合法的；反过来，一张图覆盖多条需求也合法，但必须写明它**确实支持哪些动作**，不能靠"图在旁边"默认覆盖。

### 2.4 不做什么

- 不要求每个 h2、每个概念、每道题都配图；
- 不用图片数量、图/文比例、`required` 条数当作质量指标；
- 不允许用一张与本任务无关的图关闭一条需求（"有图"≠"这条需求被满足"）。

## 3. 素材选择与降级阶梯

按顺序尝试，前一级能满足就不跳级：

| 级 | 做法 | 采用条件 | 必须检查 |
|---|---|---|---|
| **L1** | 用已有解析图（MinerU 等 `images/`） | 图完整、清晰、与上下文对应 | 是否被裁掉端子/图例/坐标轴；是否为同一图的缩略图 |
| **L2** | 取文档内嵌图及其上下文 | L1 缺图或图不完整 | 上下文标题、图注是否随图一起取到 |
| **L3** | 回到原始页面渲染 + 裁剪 | 图为矢量/组合对象，抽图丢线；或扫描页局部图 | 裁剪边界是否包含端子、极性标记、图例、条件文字 |
| **L4** | 重绘（SVG/教学简化图） | 原图过密、含无关信息、需要教学简化；或原图不可用 | **结构必须逐项核验**（§5），并在图注标明"依原文重绘" |
| **L5** | 引入外部权威资料 | 前四级都无法支撑该需求 | 标注为补充性质、写明来源，不与课程口径混用 |

规则：

- **重绘不是默认选项**。能从 L1–L3 拿到正确原图时，优先用原图——原图本身就是考试口径。
- 重绘只承担"结构教学"职责；一旦涉及精确参数、器件型号、考试原题图形，回到原图。
- 任何一级都可以判定"当前不可行"，但必须写清原因与影响（哪条 `vr_id` 因此未满足）。

### 3.1 原题复现、辅助图与教学改编

- **原题复现**：可获得的原图及参数是证据，必须保留并与题干同时可见。不得为统一风格静默换图、改参数或纠正单位。材料有疑点时记录双方依据，不以“看起来合理”定案。
- **辅助重绘**：可以另加标注图、简化图、放大图；标为 `teaching` 并与原图区分，保持题目条件，核对连接/方向/参数以及解答。原题图已满足需求时，不强制增加辅助图。
- **教学改编**：用户授权讲解/练习设计时可创建改编题，明确改变的条件和来源，并按新配置计算答案。不得把改编图与原题答案拼在一起，或冒称考试原题。
- **原图缺失**：有可靠的题干/连接/参数依据才可重建并标明依据；不能确认的部分记 `open-issue`。缺关键材料时继续可独立完成的部分，不猜出一张图关闭缺口。
- guided 默认复用原图与已核验组件；需新结构时先做最小示范。autonomous 可自行决定增加辅助图或授权范围内的改编，提供等效核验，无需为了可逆的表达选择反复询问。改变学习目标、考试口径或已有用户明确要求时才确认。
- 裁图保留本题所需条件、单位、图例及对照编号；题面与图分开提取时建立稳定关联。原图对照保留不能被折叠的解答替代。

## 4. 技术边界（不要假设抽图 = 拿到图）

- PDF 里的"图"可能是位图、矢量对象、纯文字排版，或三者组合。**单独导出图片对象会漏掉线路、箭头、标注**（这类图形常被拆成上百个矢量片段）。
- 扫描页的局部图，可靠路径是"整页渲染 → 按区域裁剪"，而不是从页面里"抠"图。
- 裁剪时必须保留：端子/引脚、极性标记、图例、单位、条件注释。为了紧凑裁掉这些，等于制造一张错误的图。
- 版面识别（版面分析、区域检测）可以在材料量大、定位困难时**提议区域**；提议结果与"这张图讲什么"仍需核验。
- 本机制**不依赖**专门训练图像识别模型，也不要求某个付费服务或大型软件。工具缺失时先采用更保守的原图/整页展示，或记录需渲染的具体页码。不把 L4 重绘当成工具不足的自动降级；结构无法核验时不重绘。

## 5. 图的三类角色，与"图-文-式-题"一致

| 角色 | 是什么 | 不能做什么 |
|---|---|---|
| **evidence** 原始证据图 | 课程原始图（截图、原页裁剪） | 不能因为"不好看"就替换成重绘；不能裁掉标注后仍称原图 |
| **teaching** 结构教学图 | 为讲清结构而绘制的简化图/重绘图 | 不能改变拓扑、极性、连接关系；不能省略"理解所必需"的支路 |
| **demo** 状态演化演示 | 交互演示某个状态变化 | 不能替代结构教学图；不能只有动效没有静态结论 |

一致性强检查（每个用图的板块至少做一次）：

1. 图里的元件/节点/符号，与正文命名一致；
2. 图中的参数值与题目给定值一致；
3. 图中方向/极性与公式里的正负号一致；
4. 图上声称的路径**真实闭合**（从电源出发能回到电源）；
5. 答案里的每一步，都能在图上指出依据。

任一条不成立时，**改图或改文，二者取实际正确的一方**，并把冲突记进 Delta Log，不要只改一处让它"看起来对上"。

工程类图的具体核验维度（电路/器件、受力、装置-模型对应、控制框图、波形）见 `domains/engineering/domain.md` §8。

## 6. 状态阶梯：不要把"文件存在"当成"验收完成"

图资产与视觉需求共用同一套状态词（写进 `course-state.json` 或施工图）：

| 状态 | 含义 | 能否算通过 |
|---|---|---|
| `located` | 已定位到源（有 `locator`），尚未取到可用图 | 否 |
| `extracted` | 已取到文件/路径，未判断完整性、未放进页面 | 否 |
| `placed` | 已进入页面，有图注与锚点 | 否 |
| `tech-checked` | 本地路径、声明和引用检查通过；实际加载另记渲染证据 | 部分（仅机械层） |
| `content-verified` | 已完成适用结构核验，图文式题一致 | 仅内容层；不推出渲染通过 |
| `open-issue` | 存在未解决冲突/不可读/待用户确认 | 否，必须写明原因与影响 |

分别记录本轮适用的机械、渲染、内容核验及依据，可用简短条目，不必新增数据库。`content-verified` 仅证明内容维度；没有实际查看或运行就不能声称渲染/交互通过。未变化且未失效的证据可沿用。

## 7. 图的增量事件

图也会随材料更新而变化。遇到下列事件时，**先更新图资产与需求表，再改页面**（对齐 `incremental-project-state.md` 的 impact 流程）：

| 事件 | 动作 |
|---|---|
| 新材料带来新图 | 新增 `fig_id`，判断覆盖哪条 `vr_id`，可能降低已有图的必要性 |
| 找到更清晰的同一张图 | 保留 `fig_id`，替换 `path`，旧路径记入 Delta Log；重跑 tech + content 核验 |
| 课程版本替换（同一图不同标注/参数） | 不覆盖旧图，登记版本差异；页面取与当前课程口径一致者，必要时并列 |
| 同图不同标注 | 作为同一 `fig_id` 的多条 `locator`/变体，注明差异来源 |
| 旧图失效、丢失、被移动 | 状态回退到 `located` 或 `open-issue`；页面不得留死链 |
| 图对应知识点或题目被移动 | 同步更新 `links` 与 `anchor`；旧锚点留 alias |
| 重绘后发现结构错误 | 立即把该图降级为 `open-issue`，修正后重做 §5 五条一致性检查 |
| 源材料之间冲突 | 记录冲突双方，按证据权重决定页面口径，不静默取舍 |

替换图片时**检查所有引用位置**（正文引用、图注编号、题目、答案、总结页），不只改当前可见那一处。

## 8. 反模式

- 把 `[IMG]` 留在文档里，然后在别处凭记忆重画；
- "这个板块还没图"→ 随便找一张相关图放上去交差；
- 交互做得漂亮，但连线接错、极性反了、路径不闭合；
- 用生成式位图（AI 出图）当作精确电路/结构连接的权威依据；
- 默认课程原图绝对正确，不做任何核对；
- 判断不了却在状态里写"已验证"；
- 为了"统一风格"把所有原图重绘一遍，丢掉原始标注与考试口径；
- 用一个空 `.diag` 容器 + 图注假装有图。

## 9. 交付前快速自检

- [ ] 材料里出现的承载知识图，是否都有 `fig_id` + `locator`？
- [ ] 每条 `required` 需求，是否有 `fig_ids` 或明确的缺口说明？
- [ ] 页面里每张图的角色（evidence/teaching/demo）是否明确？
- [ ] 重绘图是否做过 §5 五条一致性检查，并在图注标明性质？
- [ ] 图、正文、公式、题目、答案是否一致（针对本轮受影响项；重组时再抽跨节代表案例）？
- [ ] 所有图资产状态是否达到 `content-verified`，或已登记 `open-issue` 及原因？
- [ ] 静态降级是否存在：JS 失效或图加载失败时，结论仍可读？
