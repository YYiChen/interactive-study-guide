# Page Archetypes · 页面原型

原型解决一个问题：**页面结构由读者任务决定，不由资料形状决定。**

课件里有什么就摆什么、预习页永远带例题训练，都是把结构写死的症状。原型的规则只有一条：先问“这个页面要替读者完成什么任务”，再定板块。

## 1. 判定流程

```
读者任务是什么？
├── 从零开始学，最终要能应付考试        → exam-prep（默认）
├── 看懂某个原理 / 实验为什么这样、怎么用 → principle
├── 已经学过，考前压缩复习 / 速查        → review
└── 都不匹配                            → custom（必须声明理由，见 §4）
```

判定依据是**用户的目的陈述**（“讲一下这个实验”“整理考前复习”“让我预习”）和材料形态（往年卷 / 实验指导书 / 课件）的共同指向，不是单一材料形状。两者冲突时以用户目的为准，并在交付时明示所选原型。

## 2. 原型定义

| 原型 | 读者任务 | 板块结构 | 例题 / 训练 | 典型触发语 |
|---|---|---|---|---|
| `exam-prep` | 零基础 → 能独立做题应考 | 总览 → 知识板块 → 📚 例题 → 📝 训练 → 🧾 总结 | 必备 | “预习”“整理成学习页”“能考试” |
| `principle` | 理解原理、实验现象与方法 | 总览 → 知识板块 → 🧾 总结 | **默认关闭** | “讲讲这个实验”“这个原理我没看懂” |
| `review` | 压缩复习、考前速查 | 总览 → 知识板块（压缩表达）→ 🧾 总结 | 默认关闭 | “复习”“速查”“考前总结” |
| `custom` | 上述不匹配 | 自行声明 | 按声明 | — |

各原型的共同约束（不随原型放松）：

- 知识板块按**读者问题**命名与划分（SKILL.md §9）；
- 每个核心概念只有一个 Canonical Teaching Location；
- 符号 / 公式首现规则、依赖审计、Solution-backward Audit 全部照跑；
- 🧾 总结是唯一复习入口；
- 图与视觉材料要求照跑（SKILL.md §14）：承载知识的图必须登记并与知识/题目关联；配图充分性按视觉需求（`visual-material.md` §2）判定，"每个板块至少 1 个视觉锚点"只是下限。
- 原型裁剪时**不要顺手删图**：删掉例题/训练 tab 时，若某条 `required` 视觉需求原本只由该 tab 的图支撑，需把图迁到知识板块或降级该需求并记录原因。
- 领域的内容原型（概念解释 / 技巧总结 / 案例分析 / 对比 / 复习速查）**映射到这四个结构原型**，不新增 `data-archetype` 取值（checker 依赖固定值）：见 `domains/ielts/page-patterns.md` §2；工程口径见 `domains/engineering/domain.md` §6。

原型之间只差**板块取舍与表达密度**，不差教学质量。

## 3. 模板裁剪步骤（以 principle 为例）

`core/assets/study-page-template.html` 是 `exam-prep` 的完整参考实现。裁成其他原型按以下顺序改，每步都要做，漏一步就出现“点了没反应 / 跳转失效 / checker 报错”：

1. **声明原型与领域**：`<body data-archetype="principle" data-domain="engineering">`，页面顶部注释写一句取舍理由（如“实验原理讲解，不含例题与训练”）并写明领域；
2. **删 tabpage 块**：删除 `<div class="tabpage" id="page-examples">…</div>` 与 `id="page-practice"` 两个整块；
3. **删顶栏按钮**：删除对应的 `<button class="tabbtn" … id="btn-examples">` / `id="btn-practice"`（按钮是静态标记，不随 TABS 自动消失）；
4. **同步 TABS 数组**：`var TABS = ["home","topic1","topic2","examples","practice","summary"]` 删掉 `"examples","practice"`；
5. **清理跳转键**：全文搜索 `goto('examples')` / `goto('practice')` / `gotoText('…')`，凡目标落在已删板块的，删除该入口或改指向；sidebar 由 DOM 自动采集（h2/h3/.qt），无需手动改；
6. **验证**：跑 `node core/scripts/check_page.js page.html`，principle 原型下不再要求 examples/practice；再手动点一遍剩余 tab、目录跳转、跨页 gotoText。

裁成 `review` 型：同样删 examples/practice，并允许把知识板块的首次教学压缩为表格 / 对照 / 决策树 / 公式卡（复习层表达），但总结里不允许第一次出现新方法。

保留 examples/practice 但用户不要求考试：不裁板块，把训练题量降下来并在总览注明用途，不要挂“必考”字样。

## 4. custom 原型的声明要求

选 custom 前必须先写下来（给用户看，不是内部想想）：

1. 读者任务一句话；
2. 板块清单：每个板块回答哪个读者问题；
3. 相对最近的内置原型，加了什么、删了什么、为什么；
4. 哪些现有硬规则仍然适用（首现规则、依赖审计、图与交互最低要求默认全适用，放松任何一条都要单独说明理由）。

已授权学习目标内可声明理由后执行；改变范围或缺少影响结果的偏好时才确认。用户已有明确确认要求仍遵守。不要把 custom 当作省略必要教学的通道；执行路径只改变过程支撑程度。

## 5. 反模式

- **打补丁式豁免**：不做原型声明，直接在 exam-prep 页面里把例题区留空或写“本节无例题”——结构撒谎，目录和 checker 都还在按 exam-prep 期待。要么裁掉，要么声明 custom；
- **按资料目录分板块**：实验指导书有几节就分几块，不问读者问题；
- **原型漂移**：页面中途从 principle 扩出例题区却不更新 `data-archetype` 与顶部注释——再扩就当一次 Material Event，重走 §3 的同步清单。
