# Content Rules

本文件只包含跨工科通用规则。具体学科公式不得写成全局强制规范。

## 1. 概念首现

第一次出现一个新概念，至少让读者知道：

- 它解决什么问题；
- 名称是什么意思；
- 与已有知识是什么关系；
- 后面会在哪里用。

不要用“显然”“容易知道”跳过零基础读者真正需要的连接步骤。

## 2. 符号首现

首次使用前解释：读法、含义、单位/量纲、上下标/点号/偏导/向量等记号、量的角色。

同一符号在不同章节或语境含义变化时必须重新声明。

## 3. 公式首现

至少回答：

- 它是什么角色：定义 / 基本定律 / 本构 / 推导 / 经验 / 近似；
- 每项是什么；
- 依赖哪些前置；
- 成立条件；
- 典型误用；
- 可行时做量纲或极限检查。

不要把“把一组量重新命名”写成“推导出了新定律”。

## 4. 推导

推导的目标不是展示代数长度，而是解释“为什么下一步成立”。

可省略熟练读者显然的机械运算，但不能省掉：
- 新方法第一次出现；
- 关键替换；
- 边界/初值进入的位置；
- 近似或舍项理由；
- 从数学结果回到物理/几何含义的解释。

## 5. 经验关系与近似

凡是经验系数、拟合关系、常见近似或简化模型，都应说明：

- 来自哪里；
- 适用范围；
- 为什么当前可用；
- 超出范围会发生什么。

不要让学生把近似当恒等式。

## 6. 图与图表

图必须服务于一个学习任务：看趋势、读参数、识别区域、理解几何或验证推导。

硬要求（不随页面原型放松）：

- 每个知识板块至少 1 个视觉锚点（图 / 交互 / 可操作几何），不允许整板块纯文字；
- **不是每张图都要可交互**。按图型分级：A 结构识别类（设备演示、部件示意、流程框图）默认静态；B 查表取值类（Moody、K_L、粗糙度、当量比等）优先可交互查表；C 关系演化类（参数敏感性 / 时间演化 / 几何关系 / 图形读法 / 方法对比 / 量级感）必须可交互，静态仅作 JS 失效时的降级兜底；
- 每张图带图注三要素：让什么变得可见 / 观察什么 / 结论是什么。

坐标轴、单位、正方向、参考状态和关键标记必须可读；图号全页唯一；多套坐标系并存时注明各自基准。三类图型的判定口径见 `interactive-patterns.md` §1。

表格用于"对比和收束"，不要在预习页一上来用大表格代替因果推进；查表取值型表格按 B 类优先做成可交互（可调量 → 对应行/数值实时可见）。

## 7. 例子

最小示范优先选择：
- 数字简单；
- 能隔离当前新知识；
- 不引入额外背景负担；
- 能让学生检查答案是否合理。

后续再增加真实工程或综合场景。

## 8. 练习

题目前不固定放大段 prep。

使用 Dependency Audit：
- 已教过 → 直接练；
- 久未使用 → recall；
- 通用缺口 → 回正文；
- 局部技巧 → bridge。

答案必须解释关键决策，不只给代数过程。

## 9. 自检

自检是可选教学组件，不要求“每页固定 4–6 题”。

适合在一个能力节点完成后，用 1–3 个高价值问题验证：
- 能否用自己的话解释；
- 能否区分易混概念；
- 能否判断何时使用；
- 能否做一个最小计算或判断。

如果自检只是重复正文句子，可以省略。

## 10. 易错点

局部易错点放在首次教学附近；跨章节反复出现的易错模式在总结中集中对照。

格式优先：`陷阱 → 为什么错 → 正确动作`。

## 11. 语言

解释要精确，但允许口语化比喻。比喻只能帮助建立直觉，不能替代正式定义。

如果比喻在边界情形会失真，应明确“比喻到这里为止”。

## 12. 真实反馈如何沉淀

用户指出某个具体学科问题时，先抽象成通用症状再写回规则。

例如：
- “某个字母突然出现” → 符号首现规则；
- “题目用到前面没教的方法” → Question Dependency + Solution-backward；
- “同一知识反复讲” → Canonical Teaching Location + recall；
- “一补资料页面就乱” → incremental impact analysis；
- “某个经验常数凭空出现” → 经验关系四件事。

不要把具体学科公式永久写进本文件。
