# Engineering Domain · 工科与工程数学

`domain=engineering` 是**默认领域**。本文件不新增学习规则，只把 core 规则收敛成工程资料的具体口径——原来写在 `SKILL.md` §10、§14 与 `core/references/*` 里的工程示例集中到这里。

## 1. 适用资料特征

- 固体/材料力学、动力学、振动、热力学、流体、传热、电路、控制、工程数学、微分方程等课程；
- 载体：课件 PPT、实验指导书、往年卷、习题解答、公式表、Lab Guide / 报告模板、教师板书照片；
- 内容形态：概念 + 符号 + 方程/公式 + 条件 + 推导 + 题型。

## 2. 加载清单

1. `../../core/README.md` 与 `../../SKILL.md`（全部 core 规则）；
2. 本文件（组织轴、图型例子、图纸核验口径、验证重点）；
3. 材料含图（电路图、装置图、框图、波形、扫描页插图）时加读 `../../core/references/visual-material.md`；
4. 涉及具体课程时按需读 `../../core/references/teaching-architecture.md`、`content-rules.md`、`verification.md`。

## 3. 学科主线（示例，不是强制模板）

模型应根据当前课程的对象与任务识别最自然的结构：

- 力学类常见：对象/几何/受力 → 方程 → 条件 → 求解 → 解释；
- 热流体类常见：系统/控制体 → 守恒 → 物性/本构/状态关系 → 假设 → 求解；
- 数学类常见：定义 → 性质/定理 → 推导/证明 → 方法 → 例题。

不要把任何一个示例当成强制模板；依赖顺序仍由 Prerequisite Graph 决定，不由课件目录决定。

## 4. 图型判定（core §14 的工程口径）

| 图型 | 工程典型例子 | 默认要求 |
|---|---|---|
| **A 结构识别类** | 设备演示、部件示意、装置照片、装配关系、流程框图 | **静态**；读者任务是“认出这是什么、在哪、怎么组合”，动效不增加理解 |
| **B 查表取值类** | Moody 图、K_L 表、等效粗糙度表、当量比、ε–NTU 关系、符号/单位速查 | **优先可交互查表**：给一个可调量（Re、ε/D、φ…），实时高亮对应行/曲线并显示完整数值 |
| **C 关系演化类** | 参数敏感性、时间演化、几何关系、图形读法、方法对比、量级感 | **按学习收益选择**：需主动操控时做交互；状态对照/连续帧足够时可静态，保留图文对应与结论 |

C 类的工程判定口径（防误判）：

- “几何关系”指**拖动会改变量与量之间的关系**（拖位置看力臂、拖长度看剖面）；只展示固定结构的是 A 类；
- 表格二分：对比/收束型（易错对照、符号汇总、方法对比）静态；查表取值型（给一个量查另一个量）按 B 类；
- 图兼有多类性质时按读者当前任务选择表达，不按 C > B > A 自动升级为交互；
- 典型 C 类触发场景：“参数变大，根会怎么移动”“振荡怎么衰减”“从衰减曲线上量出 δ”“换个摆长周期怎么变”。

图容器、四种交互代码骨架、静态降级与图注三要素见 `../../core/references/interactive-patterns.md`。

A/B/C 只决定"要不要交互"，不决定"用哪张图"：原始证据图（考试口径）优先保留，重绘只在原图不可用或需教学简化时使用，且必须核验结构（§8）。图的三种角色见 `../../core/references/visual-material.md` §5。

## 5. 内容口径

- **记号**：上下标、点号、偏导、向量、矩阵必须解释；同一符号在不同章节含义变化时重新声明（`../../core/references/content-rules.md` §2）；
- **公式角色**：定义 / 基本定律 / 本构 / 推导 / 经验 / 近似必须明确，可行时做量纲或极限检查（同上 §3）；
- **推导**：可省略熟练读者显然的机械运算，但不能省掉新方法首现、关键替换、边界/初值进入位置、近似理由、数学结果回到物理含义（同上 §4）；
- **经验关系与近似**：说明来源、适用范围、为什么当前可用、超出范围会怎样（同上 §5）；
- **数值检查**：能否回代、是否满足守恒/方程/边界（`../../core/references/verification.md` C 节）。

## 6. 原型与练习

- 默认结构原型 `exam-prep`（例题与训练必备）；
- 实验/原理讲解用 `principle`（默认关闭例题训练）；考前压缩用 `review`；
- 练习梯度与 Solution-backward Audit 见 `../../core/references/teaching-architecture.md` §6–§7。

## 8. 图纸核验口径（工程图的结构正确性）

核心机制在 `../../core/references/visual-material.md`（读取契约、素材降级、五条一致性检查）。本节只给**按图型选择适用项**的核验维度——不是每张图都要逐条填表。

### 8.1 电路与器件图

| 维度 | 核什么 | 典型错误 |
|---|---|---|
| 符号与端子 | 元件符号是否正确（电阻/电容/二极管/三极管/运放/电机），端子名称是否与正文一致 | 用方块代替二极管，看的人无法判断极性；`B/C/E` 与 `b/c/e` 混用 |
| 极性、参考地、测量方向 | 电源正负极、参考地位置、电压/电流表接法 | 电源符号方向与方程符号相反；地画在悬浮节点上 |
| 电流参考方向 | 箭头方向与方程里的正负号是否对应；假设方向是否声明 | 图上箭头标"流入"，方程按流出写 |
| 交叉与连接点 | 交叉处是否有连接点圆点；T 型连接是否明确 | 该连的没点、不该连的点上，读者无法判断拓扑 |
| 旁路 | 元件是否被导线短接；开关/保护支路是否真的并在正确位置 | 画了电阻但两端被一条线直连 |
| 开关、二极管、晶体管状态 | 通断状态、正偏/反偏、NPN/PNP、饱和/截止是否与当前讨论一致 | 说"正偏导通"却画成反偏；PNP 按 NPN 画 |
| 参数一致性 | 图中阻值/容值/电压与题干、公式、答案一致 | 图 10 Ω、题干 5 Ω、答案按 5 Ω 算 |
| 路径闭合 | 声称的电流路径能否从电源出发回到电源；路径上的元件顺序与文字叙述一致 | 文字写"D1→M→D3"但图中这三者不构成一条闭合回路 |

### 8.2 其他工程结构

| 图型 | 核什么 |
|---|---|
| 受力/自由体图 | 力的方向、作用点、坐标轴、约束与边界条件；箭头是否落在正确构件上 |
| 装置图 ↔ 简化模型 | 一一对应关系：实物里的哪个部件对应模型里的哪个质量/弹簧/阻尼；被忽略的部件要说明 |
| 控制框图 | 求和符号的正负、支路合并点、反馈方向（负反馈箭头指向求和点）、信号名与传递函数符号一致、单位反馈假设写明 |
| 波形图 | 横纵轴物理量与单位、相位参考点、幅值基准、采样/理想化假设 |
| 实物照片与接线示意 | 分清"这是实物长什么样"和"这是电气怎么接"；两者不能互相顶替 |
| 特性曲线（Bode/极化/莫尔圆等） | 坐标类型（对数/线性）、关键点标注、渐近线与实际曲线的区别 |

### 8.3 禁止与不确定

禁止：

- 凭文字想象关键连接后直接出 SVG；
- 静默用自绘 SVG 顶替原题证据，或把改编配置与原题答案混用；辅助重绘/教学改编按 `../../core/references/visual-material.md` §3.1 标明性质与核验，两种执行模式遵守相同正确性要求；
- 用"看起来专业的矢量图"掩盖结构未核验；
- 把生成式位图当作精确电路/结构连接的权威依据；
- 默认课程原图绝对正确（原图可能本身就简化、有笔误或与本次口径不同）；
- 判断不了却在状态里写"已验证"。

不确定时的正确做法：把该图记为 `open-issue`，写明**哪一项无法确认、影响哪个知识点或题目、需要什么材料才能确认**（原页更高分辨率、教师说明、教材图）。不要用"再加一张无关图"关闭问题。
