# IELTS Domain · 雅思学习资料适配器

`domain=ielts` 的入口。本文件**不定义**雅思考什么，也**不预设**网页结构。

## 1. 定位与边界

**做**：把用户长期积累的 IELTS 资料（教师 PPT、课堂笔记、个人总结、语言素材、范文、练习、参考材料）分析、整理、重构为一个**个人雅思知识系统**，并能持续增量维护。

**不做**（出现以下倾向就停下来）：

- 错题系统 / AI 陪练系统 / 刷题 App；
- 单纯的笔记模板或资料归档；
- 固定章节的雅思教材生成器；
- `PDF → HTML` 的格式搬运——目标是 **资料 → 知识**。

判据：产出的页面上，每一条内容都应能追到用户的一份材料或一次明确的模型补充（`../../core/references/source-expansion-policy.md`）。

## 2. 本域不决定内容结构

不预设 `Reading / Listening / Writing / Speaking` 作为固定网页目录。

原因：不同人的雅思笔记结构不同——可能只有口语笔记，可能是“老师按题型讲、自己按失分点记”的混合材料，也可能按课程批次组织。

若最终结构里出现了四科，那必须是**从真实资料归纳、并经用户确认**的结果，不是本域的默认值。

同理，不预设：一定有词汇表、一定有错题库、一定有范文、一定有官方评分标准原文。

## 3. domain 判定信号

用户说法：IELTS / 雅思 / 剑桥真题 / 大作文 / 小作文 / 口语 Part / band / 机经 / 同义替换。

资料特征：考试题型名、评分标准或评分维度、范文与批改、真题题干、题卡、听力场景词、题库编号（如 C19 T2 P1）。

与工程资料混在同一批文件里时：**拆成两个项目分别处理**；无法拆时按主领域 + 附属领域交付，并写明哪个文件属于哪个领域。

## 4. 加载清单（按此顺序）

1. `../../core/README.md`（core 硬规则 + Domain Adapter Contract）；
2. `material-taxonomy.md`：这批资料分别是什么；
3. `knowledge-units.md`：知识单元怎么切、怎么并、来源怎么记；
4. `organization.md`：组织轴 + 从数据推出信息架构 + IA 草案流程（**写页面前必须完成**）；
5. `page-patterns.md`：语言学习页面原型与视觉锚点口径；
6. `incremental.md`：新材料到来时怎么并入（对应 SKILL.md §12）。

## 5. Core 概念在本域的落地

| Core 概念 | IELTS 中的形态 |
|---|---|
| Symbol Registry | 术语 / 表达 / 词伙 / 题型名 / 标记符号登记表 |
| 符号首现 | 术语与题型名首次出现必须解释：是什么、什么时候用、与相邻概念的区别 |
| 公式首现 | 规则 / 技巧 / 模板 / 评分标准的首次出现：来自哪里（老师 / 教材 / 范文 / 个人经验）、适用条件、典型误用 |
| 推导 | 解题路径与推理链：从题干信号到作答动作，每一步为什么 |
| 例题 | 示例分析、范文、真实作答与批改对照 |
| 能力检查 | 一次真实作答动作（能定位 / 能判断 / 能产出），不是“记住了” |
| Assessment Status | 考试权重证据（老师强调、多来源重复、真题命中）；未观察到记 `unknown` |

## 6. 硬约束（继承，不放松）

- 每个核心概念一个 Canonical Teaching Location；
- 首现规则（术语、规则、模板、评分口径）；
- 不缩水：并入新资料前先做 Coverage Baseline；
- 来源可追溯：每个知识节点保留来源（见 `knowledge-units.md` §5）；
- 未观察到 ≠ 不考；缺什么记 `unknown`，**不得凭空补考纲内容**；
- 图与交互最低要求照跑（本域口径见 `page-patterns.md` §3）；
- 交付前四道 Gate + `node core/scripts/check_page.js`。

## 7. 未知优先原则

资料里没有的类型、技巧、素材，**不得出现在页面上**。

“其他 / 未知”是合法类型（`material-taxonomy.md` §4）：先登记证据，等更多材料出现再定名。

模型可以按 core 的 Necessary Closure 补必要前置（标注为模型补充），但不得补“雅思应该有的模块”。

## 8. 交付前必须做的事

写 HTML 之前，先给用户一份 **IA 草案**（模板见 `organization.md` §5）并等确认。用户确认后才选页面原型、生成页面。

这不是客套：雅思资料形态差异极大，模型凭经验猜结构几乎一定会与用户笔记错位。

## 9. 反模式

- 因为“雅思就是四科”就先建四个目录再往里塞；
- 把老师的技巧与自己的经验总结混成一段（来源丢失）；
- 一次出现的表达被当成高频素材；
- 用模型自己写的“标准答案 / 范文”冒充资料内容；
- 同一技巧在多个文件出现 → 生成多个重复页面。
