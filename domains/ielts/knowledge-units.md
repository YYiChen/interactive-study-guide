# Knowledge Units · 知识单元抽取、合并与来源

## 1. 什么是一个知识单元

一个**可被独立使用的最小能力单元**：读者能拿它复述、判断或执行一个动作。

判定问句：删掉它，会不会有某个已观察到的任务做不了？会 → 是知识单元；不会 → 它是素材或装饰。

典型单元：题型概念、解题动作、语言功能、表达族、评分维度、时间与节奏策略、重复出现的失分模式。

## 2. 不按文件顺序切

切分与资料顺序无关：

- 同一动作出现在多个文件里 → 合成一个单元；
- 一个文件里讲了五件互不相关的事 → 拆成五个单元；
- 一段话只是某单元的素材 → 挂到该单元下，不独立成节。

## 3. 合并信号

该合成一个节点：

- **重复出现**：同一技巧 / 术语在 ≥2 份材料中出现；
- **共同依赖**：多个技巧依赖同一前置概念 → 该前置单独成节点并前移；
- **同功能**：不同表述（同义替换、不同模板）承担同一语言功能 → 合成“功能节点 + 素材清单”；
- **同题型**：按题型反复出现的注意事项 → 合成题型节点；
- **同失分模式**：用户多次犯同一类错 → 合成经验节点，标“个人口径”。

不该合并：

- 看起来像但**动作不同**的东西（“定位”是找位置，“判断”是下结论）→ 两个节点并互相链接；
- 同一话题下但用途不同的素材（口语用 vs 写作用）→ 同一功能节点的两个分组，或两个节点，由使用场景决定。

## 4. 节点字段

`id`（稳定 ID，如 `K-WRITE-003`，展示标题可改）、`title`、`kind`（概念 / 技巧 / 素材 / 题型 / 表达 / 经验 / 评测 / 未知）、`ability`（读者能用它做什么动作）、`prerequisites`、`sources[]`、`personal_marks[]`、`assessment_status`、`canonical_anchor`、`aliases`。

## 5. 来源记录（provenance）

每个节点必须能回答“这条是从哪来的”。一条 source 记录包含：

- `material_id`；
- `locator`：页 / 段 / 题号 / 时间码（有多少记多少，**不编造**）；
- `role`：教师口径 / 课堂补充 / 个人总结 / 练习反馈 / 参考材料；
- 时间或课次（材料里有才记）；
- `emphasis`：老师课上强调、用户自己加粗 / 星标 / 感叹号——原样记录，不改写；
- `quote`：个人总结与提醒尽量保留原句（可短），不要改写成模型的措辞。

一个节点有多条来源是正常的：**多来源分别列出**，不要只留一条，也不要把来源合并成“老师说过”。

## 6. 冲突与修订

同一件事出现不同说法（两位老师、课件 vs 笔记、旧笔记 vs 新笔记）：

1. 识别来源与时间；
2. 判断是纠错、简化，还是适用条件不同；
3. 节点只保留一个清晰主口径；
4. 差异用 note 说明（谁说的、什么时候、差在哪），不静默覆盖；
5. 在 Delta Log 记为 `CORRECTION_OR_CONFLICT`，必要时请用户裁决主口径。

## 7. 个人痕迹保留规则

老师强调、用户自标注、个人经验总结 = **一等公民**，不得在“摘要式整理”中被删掉：

- 保留原始措辞（短引用）＋ 系统化解释（为什么成立、什么时候不成立）；
- 与教师口径冲突时不删任何一方，标清来源后并存；
- 个人经验标“个人口径”，不冒充官方或教师结论。

## 8. 反模式

- 一个技巧在五个文件里出现 → 生成五个页面；
- 只留一条来源，其它来源丢失；
- 把用户的经验总结压缩成一句中性描述（原意与语气丢失）；
- 把素材（词、句、短语）升级成知识节点单独占一节；
- 给节点起“其他 / 杂项 / 补充”式标题。
