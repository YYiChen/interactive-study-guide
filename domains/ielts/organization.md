# Organization · 从资料推出信息架构

## 1. 三条硬原则

1. **不按输入顺序组织**：`PPT1 / PPT2 / 第3课` 不是结构；
2. **不强行补充不存在的信息**：不假设用户有四科完整笔记、词汇表或错题库；
3. **保留个人学习痕迹**：老师强调、自标注、经验总结按一等公民处理（`knowledge-units.md` §7）。

## 2. 组织轴是候选，不是清单

从数据里选一个（或少数几个组合）作为主组织轴：

- 按**能力动作**：定位、判断题干、抓主旨、展开论证、时间分配……
- 按**题型 / 任务类型**；
- 按**语言功能**：表达观点、让步、举例、比较……
- 按**失分模式**：用户自己的错因；
- 按**考试流程阶段**：读题 → 定位 → 作答 → 检查。

判断依据：哪种轴能让最多知识节点**只出现一次**，且依赖关系最顺。

选不出来，说明资料还不够：先按局部（单份材料内部）整理，把不确定处记为 `unknown`，不要为了“结构完整”硬造板块。

## 3. 三层结构

- **知识节点**：一个可独立使用的最小单元（`knowledge-units.md`）；
- **知识板块（h2）**：一组节点共同的读者问题，例如“看到这种题干先做什么？”；
- **页面集合**：板块多时拆成多个 HTML，用统一 sidebar 与跳转串联；板块少时合并成一页。

板块命名与 core 一致：回答一个读者问题或动作，不用“理论补充 / 其他 / 资料汇总”这类标题。

## 4. 从数据到结构的流程

1. 材料清单 + 类型判定（`material-taxonomy.md`）；
2. 抽知识单元 + 合并（`knowledge-units.md`）；
3. 聚类：共现、依赖、同功能、同题型；
4. 选组织轴，给每个板块写一句读者问题；
5. 覆盖核对：每个单元有归宿；每份材料被用过，或明确登记“暂不纳入 + 原因”；
6. 产出 IA 草案（§5）交用户确认；
7. 确认后才选页面原型、写 HTML。

## 5. IA 草案模板（给用户看的）

- **本次纳入的资料**：清单（来源名 / 类型 / 课次或日期）；
- **暂不纳入的资料**：清单 + 原因（重复 / 解析不清 / 与当前范围无关）；
- **建议组织轴**：一句话 + 为什么是它；
- **板块草案**：板块名 / 它回答的读者问题 / 包含哪些知识节点 / 来源；
- **缺口**：哪些地方资料不足（`unknown`），需要用户补什么；
- **个人痕迹的处理方式**：强调与经验怎么展示；
- **待确认问题**：2–5 个具体问题（不要只问“这样可以吗”）。

用户改动后同步更新草案，再动手写页面。

## 6. 缺口与边界

- 资料没覆盖的板块：**不建**，但也不写“不考”；
- 已确认题型所依赖的前置即使资料没讲，也要按 core 的 Necessary Closure 补齐，并标明是模型补充；
- 不把雅思官方考纲当成“用户资料”写进页面（除非用户提供了对应材料）；
- 资料内部矛盾时按 `knowledge-units.md` §6 处理，不要替用户选一个然后静默覆盖。

## 7. 反模式

- 按文件夹或文件名分板块；
- 先建“听力 / 阅读 / 写作 / 口语”四科目录再往里塞内容；
- 把“技巧”和“素材”混进同一板块（一个是动作，一个是库存）；
- 用通用雅思常识填满资料不足的板块；
- 结构定稿前就生成 HTML。
