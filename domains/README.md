# Domains · 领域适配器

本目录只放**领域知识**：这类资料怎么读、知识怎么成节、页面怎么表达。

通用教学机制、页面引擎与检查器在 `core/`；调度规则在 `../SKILL.md` §0。领域规则**不改变** core 的学习逻辑，只调整组织轴与表达口径。

## 1. 注册表

| domain id | 状态 | 入口 | 适用资料特征 | 备注 |
|---|---|---|---|---|
| `engineering` | 默认 | `domains/engineering/domain.md` | 工科与工程数学课程资料：课件、实验指导书、往年卷、公式推导 | 不新增规则；收敛 core 规则的工程口径与图型例子 |
| `ielts` | 已注册 | `domains/ielts/domain.md` | IELTS / 语言学习资料：教师 PPT、课堂笔记、个人总结、语言素材、练习与范文 | **不预设听说读写四科结构**；结构由真实资料推出并经用户确认 |

## 2. 判定与调度（对齐 SKILL.md §0）

- 用户显式指定领域 → 直接采用；
- 未指定 → 按资料特征判定；
- 判不准，或一批资料横跨多个领域 → 问用户，不要默默猜；横跨时指定主领域 + 附属领域，并在交付说明里写明；
- 领域未注册 → 按 `custom` 处理：先写清读者任务、板块清单、与最近领域的差异、哪些 core 硬规则仍适用，用户确认后再动手。

## 3. 新增一个 domain 的步骤

1. 建 `domains/<id>/domain.md`，按 `core/README.md` §4 的 Domain Adapter Contract 写全 8 项；
2. 在本文件 §1 注册表加一行；
3. 在 `../SKILL.md` §0 的已注册领域列表加一项；
4. 自检：拿一份该领域的真实资料走一遍“判定 → 资料类型 → 知识单元 → IA 草案”，确认全程不依赖任何未写的规则；
5. 不修改 `core/` 的规则文本；要改 core 就单独说明它对所有领域的影响。

## 4. domain id 命名

小写 kebab-case，与目录名一致（Windows 上大小写不敏感，但写文档时统一小写）。

用户的别名说法（“雅思”“IELTS”“剑桥真题”）登记在对应 `domain.md` 的判定信号里，不另建目录。
